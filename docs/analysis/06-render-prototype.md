# Прототип рендера (тетрадный лист, Phaser 4)

Код: [`packages/client`](../../packages/client). Дата: 2026-10-11. Это однодневный прототип-«ворота» из [ADR 0001](../adr/0001-tech-stack.md):
проверить, что Phaser 4 тянет карту с сотнями юнитов и что рисование приказа от руки ощущается так, как задумано.
Пометки: **[проверено]** — запущено и измерено в этой сессии; **[не проверено]** — не запускалось.

## Запуск

```bash
npm install
npm run dev        # http://127.0.0.1:5173
npm test           # тесты ядра (36) и клиента (4)
```

## Что построено

| Что | Где | Как устроено |
|---|---|---|
| Тетрадный лист | `src/paper.ts` | Плитка 640×640 px, рисуется в canvas: зерно бумаги и линии клетки. Клетка листа = 1 единица длины (диаметр юнита) |
| Рисованные юниты | `src/paper.ts` | Кружок из двух неровных обводок, цвет ручки игрока и метка внутри (точка, плюс, крест, треугольник): различимы и без цвета |
| Рельеф штрихами | `src/paper.ts` | Стена — штриховка и жирная рамка, бездорожье — точки, дорога — две линии. Растр данных ядра остаётся скрытым |
| Группы и приказы | `src/BattleScene.ts` | ЛКМ/рамка — выбор; ПКМ-протяжка — маршрут группе; Shift+ПКМ — атака в точку; D — оборона; Del — снять приказы; приказ группе стоит 1 AP |
| Превью маршрута | `previewMove` из ядра | Достижимая за ход часть — сплошной чернильной линией у каждого юнита, весь нарисованный маршрут — пунктиром |
| Упрощение линии | `src/draw.ts` | Рамер—Дуглас—Пекер «сверху вниз» до лимита ядра (16 точек) |
| Туман | `RenderTexture` | Затемнённый лист, «проявленный» кругами обзора юнитов активного игрока; враги вне обзора скрыты |
| Проигрывание хода | `BattleScene.update` | Тики с интерполяцией, выстрелы чернильными линиями, гибель — крестик. **Показывается только то, что видит активный игрок** |
| Hotseat | HUD | Клавиши 1–4 — за какого игрока ходить; боты (из `@cardboard/sim`) играют за остальных |
| Настройки | HUD | Режим залпа (`start` / `zone` / `end`), размер группы, AP за ход, скорость тика — как просил владелец |

## Проверено

- **Рендер работает, ошибок в консоли нет.** Phaser 4.2.1 (WebGL): лист, 500 юнитов, туман, рельеф, рамка карты.
- **Нагрузка** (встроенный браузер, `WebKit WebGL`, железо видеокарты неизвестно):
  - ~10–11 мс на кадр при ручном шаге игры, 500 юнитов + туман, любое увеличение (0.3–1.5);
  - **60 fps на простое** и **46–48 fps при непрерывном зуме и сдвиге камеры** с 441 юнитом (замер включает мой собственный цикл).
- **Ход в клиенте:** `resolveTurn` на 500 юнитах и 4 игроках с ботами — 22–29 мс на первом ходу (холодный JIT), 7–10 мс на следующих; 15 ходов подряд без ошибок, 500 → 441 юнит.
- **Реальный ввод:** выделение рамкой и зум колесом — настоящей мышью. ПКМ-протяжка — синтетическими событиями указателя: ~31 сырая точка → 6 точек, приказ создан для 5 юнитов.
- **Тесты:** упрощение линии (4 теста): прямая → 2 точки, излом сохраняется, лимит 16 точек, целые координаты.

## Находки (баги и уроки)

1. **Упрощение линии вело себя скачком** (нашёл тест): метод «поднимать допуск, пока уложимся в 16 точек» превращал сложную кривую сразу в 2 точки.
   Исправлено выбором наиболее значимых точек до лимита.
2. **Утечка через проигрывание хода в самом клиенте:** я показывал гибели и выстрелы из полного лога, и далеко за обзором появлялись крестики. Исправлено:
   клиент показывает событие, только если оно в обзоре активного игрока (круги его юнитов в начале и конце интервала) или касается его юнитов.
   Проверено: все нарисованные гибели чужих юнитов лежат в обзоре игрока.
3. **Превью маршрута расходится с исполнением в плотной толчее:** до 333 пунктов (3.3 единицы при пути 5 за ход), группа из 6 идёт сквозь собственный
   лагерь, где её расталкивают. Превью по замыслу считает юнит одиноким. Для одинокого юнита совпадение точное ([03](03-spike-results.md)).
   Для интерфейса важно: нужен знак «возможна толкотня» или превью с учётом своих.
4. **Phaser 4:** `RenderTexture` буферизует команды до явного `render()` (без него туман был невидим); при `Scale.RESIZE` на старте высота канваса нулевая
   (камера получала отрицательный зум): размер берётся из окна.
5. **Измерения в скрытой панели браузера недействительны:** `requestAnimationFrame` там почти не идёт («3 fps»). Реальные цифры получены, когда панель была видна.

## НЕ проверено

- Видеокарта и браузеры: один движок (`WebKit WebGL`), Firefox/Safari/мобильные не проверялись.
- Карта **60×60 единиц**, а не 100×100 из плана ворот; 441–500 юнитов.
- ПКМ-протяжка физической мышью, Shift+ПКМ (атака), клавиши Enter, D, Del, 1–4, переключатель режима залпа, лимит группы и AP в HUD,
  смена игрока в hotseat, изменение размера окна — код есть, вручную не прогонялись (создание приказов проверено вызовом методов сцены).
- Подозрение на производительность: статичные `Graphics` (рельеф, приказы) перерисовываются каждый кадр; запечь их в текстуру — вероятная оптимизация. Не измерено как узкое место.
- Ощущение игры: ничего о «как в Lines of Battle» по существу не проверено, нужен живой пользователь.

## Вывод для ADR 0001

Phaser 4 для этой задачи подходит: ворота пройдены по измерению на 500 юнитах (≥46 fps в тяжёлом сценарии, 60 fps на простое) в одном окружении.
Решение остаётся «предложено»; окончательно подтвердить после проверки на вашей видеокарте.
