# Вопросы владельцу

Решения по геймдизайну и по тому, что имеет цену, принимаете вы. Ниже то, без чего дальше идти опасно или дорого
переделывать. По каждому есть рекомендация, но она не решение.

## 1. Название

«Закалка Стали: Директива» вы не принимаете. Пока код и репозиторий живут под рабочим именем **CardboardRTS**.
Заметка: «RTS» в названии репозитория неточно — жанр по ГДД это пошаговая тактика с одновременными ходами (STBS).

Идеи для вдохновения (не решение, придумал сам — никакой проверки на занятость названий не делал):

- Опираются на тайные приказы: «Печать», «Запечатано», «Приказ в конверте», «Сургуч», «Красный карандаш».
- Опираются на «картон»: «Картонный фронт», «Штаб из картона», «Картонная директива», «Бумажный штаб».
- Англоязычные: *Sealed Orders*, *Cardboard Command*, *Paper Front*.

Вопрос: что должно быть главным в названии — приказы (тайна, одновременность) или «картон» (внешний вид)?

## 2. Что значит «картон» визуально

От ответа зависит рендер ([ADR 0001](adr/0001-tech-stack.md)):

- (a) плоская 2D-карта с нарисованными/запечёнными текстурами картона и тенями → Phaser 4 (рекомендация);
- (b) настоящие вырезанные фигурки с динамическим светом, тенью и «вставанием» → three.js с ортокамерой.

## 4. Куда направить массовость

Мой совет: старт — режим A (много параллельных 1v1/2v2 с ботами и асинхронными ходами), затем B (6–8 асинхрон), и только
потом C/D/E. Причина: лобби на 16 человек онлайн не соберётся ([02](analysis/02-mass-multiplayer.md)). Устраивает?

## 5. Связь с планом роста в .NET

В ваших заметках есть цель — C#/.NET-бэкенд. Правила игры должны быть одним кодом для клиента и сервера, поэтому
я выбрал TypeScript. Вариант совместить цель: .NET делает сервисы *вокруг* игры (аккаунты, рейтинги, платежи,
матчмейкинг). Нужно ли использовать проект как полигон для .NET? Если да — это меняет архитектуру сервисов, не ядра.

## 6. Что я бы сделал следующим и чего не буду делать без «да»

- Только после вашего «да»: любые решения по правилам из таблицы выше, смена названия в репозитории, публикация на хостинге,
  регистрация аккаунтов и платных сервисов.
